# AirBridge must win where vendors stop

**Bottom line in plain words:** The idea as written today ("link my computers so my agents can hand tasks to each other, $15 a month") is **not a strong business yet**. The main reason is that the big companies already ship most of it for free. Claude Code can now send messages from a session on one of your computers to your sessions on other computers ([Claude Code docs](https://code.claude.com/docs/en/cross-session-messaging.md)). OpenAI Codex can move a chat and its Git state between your computers ([Codex docs](https://learn.chatgpt.com/docs/remote-connections)). Tailscale gives free private networking for personal use ([Tailscale](https://tailscale.com/blog/pricing-v4)). Also, people ask much more for "control my agent from another device" than for "agents talk to each other across my machines". The second request is real but small, and many of the loudest voices are people building their own tools ([GitHub #28300](https://github.com/anthropics/claude-code/issues/28300)). **There is still a narrow opening.** No vendor connects Claude to Codex to Cursor. The vendor features send your data through their own servers. Anthropic's feature only sends plain text, and it does not work for API-key, Bedrock, Vertex, or zero-data-retention users. So the wedge is **"one private bridge for all your agents, on all your computers, that moves real files and diffs"**. Sell it first to solo power users who already spend $100–$200 a month on AI and use two or more vendors on two or more machines. Test $8–10 a month with a free tier next to $15. Before you build more, run about 15 interviews and a two-week landing-page test (plan at the end). If those fail, the better product could be config and session sync, which has more visible pain.

How to read this report: **"Evidence"** means a cited source says it. **"My estimate"** or **"speculation"** means it is reasoning from the evidence, not a measured fact. The research did not include Reddit data, and no survey measures how many developers use agents on more than one machine. That is the biggest unknown in this whole report.

## Demand is real for remote access, but thin for agent-to-agent handoff

The research found four kinds of multi-machine need. They differ a lot in strength, so it helps to rank them.

**1. "Let me control my agent on machine A from device B." This is the strongest need, and vendors now serve it.** The OpenAI Codex discussion asking for remote control got **195 votes and about 55 participants**. One user said, "I'm actively choosing competitors over Codex for this feature alone" ([GitHub codex #9200](https://github.com/openai/codex/discussions/9200)). Both OpenAI and Anthropic shipped this feature in 2026 ([Claude Code docs: Remote Control](https://code.claude.com/docs/en/remote-control)).

**2. "Keep my setup the same on all my machines." This pain is common.** A May 2026 blog post is titled "My Claude Code setup lived on three machines and none of them agreed". The writer describes "a skill I wrote on Tuesday that simply did not exist on the other two" ([dev.to](https://dev.to/landb/my-claude-code-setup-lived-on-three-machines-and-none-of-them-agreed-17ok)). Many small tools try to fix this, such as claude-nomad and claude-brain ([claude-nomad](https://funkadelic.github.io/claude-nomad/), [claude-brain](https://dev.to/toroleapinc/i-built-a-tool-to-sync-your-claude-code-brain-across-machines-5a1o)). When many people build the same fix on their own, the pain is real.

**3. "Move my session to another device without planning ahead." People describe this clearly, but few vote for it.** One Claude Code issue said, "I think about 'my mini PC' and 'my laptop', not about 'session 48293'". It got only one or two reactions and the bot closed it as stale in June 2026 ([GitHub #49657](https://github.com/anthropics/claude-code/issues/49657)).

**4. "Let the agent on one machine hand a task or code to the agent on another machine." This is exactly AirBridge, and it is the weakest signal.** The best evidence is Claude Code issue #28300, opened February 2026. The author wrote, "the moment a project spans two machines, the human becomes the bottleneck again". Another user said, "I am literally the human message bus between the two instances" ([GitHub #28300](https://github.com/anthropics/claude-code/issues/28300)). These are excellent quotes for your landing page. But the issue has only **about 19 commenters**, and most comments after March promote the commenter's own tool. That pattern usually means "builders find this fun", not "many users will pay".

Open-source traction tells the same story. The most popular agent-messaging project, claude-peers-mcp, has **about 2,200 stars, but it works only on one machine** ("Everything is localhost-only") ([GitHub](https://github.com/louislva/claude-peers-mcp)). The closest copy of AirBridge, Latth/agent-bridge, is cross-machine, cross-vendor, encrypted, and uses a pairing code. It had **2 stars** when checked ([GitHub](https://github.com/Latth/agent-bridge)). So people like "agents talking to each other", but the cross-machine version has not pulled users yet.

Who has more than one machine? In a large November 2026 Hacker News thread about AI agent setups (573 points, 718 comments), roughly 3–4 of about 16 top comments that were checked described several machines. One person runs agents "across a fleet of 20 machines linked together with tailscale and ssh". Another said, "I do desperately need to figure out some way to get stuff off my laptop" ([HN](https://news.ycombinator.com/item?id=50366117)). This is a small sample, not a survey. The same thread also shows the opposite trend. One user said, "I haven't had an agent do anything from my laptop in a month or two", because everything runs in cloud sandboxes ([HN](https://news.ycombinator.com/item?id=50366117)). **If work moves to the cloud, linking personal machines matters less.** The exceptions are jobs that need local hardware: a GPU, a Windows or Mac toolchain, a simulator, or a private network.

One specific pain point stands out: **Mac to Windows.** In July 2026, Cursor's Remote Control from a MacBook to a Windows machine failed, and Cursor staff said they were "tracking a fix internally" ([Cursor forum](https://forum.cursor.com/t/remote-control-from-mac-to-windows-spawns-cursor-agent-locally-and-fails-with-enoent-on-c-paths/166356)). Many other Cursor forum reports describe agents breaking over remote SSH between operating systems ([Cursor forum](https://forum.cursor.com/t/remote-ssh-to-windows-host-all-agent-skills-fail-to-load-including-built-in-create-skill-cursor-3-1-15-macos-windows/158377)). AirBridge plans Mac and Windows support, so this fits.

**Answer to question 1:** Yes, there is real demand around multi-machine agent work. But the specific "agent hands work to agent" need is **niche and not yet proven to be paid demand**. My estimate is that it is a power-user feature, not a mass-market product.

## Anthropic, OpenAI and Cursor already ship the single-vendor version

This is the most important finding. In 2025 this idea had open space. By November 2026, much of it is taken.

Read the "limits" column carefully, because **your product lives in those gaps**. Four gaps remain open (evidence for the gaps, my reasoning for why they matter).

**First, no one bridges vendors.** Every vendor feature works only inside its own product. Claude cannot hand a task to Codex on another machine. Each vendor wants to keep you inside its own subscription, so this gap is the hardest for any one of them to close.

**Second, every vendor feature goes through vendor servers.** Anthropic stores the transcript. Users on API keys, Bedrock, Vertex, LLM gateways, zero-data-retention, or HIPAA setups **cannot use Anthropic's feature at all** ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). A peer-to-peer bridge serves them.

**Third, Claude's messages carry text only.** Codex moves Git state, but only between Codex hosts. A bridge that moves files, diffs, and Git bundles between any agents does more.

**Fourth, cross-OS support is still buggy** in at least Cursor.

The lesson from similar tools is harsh. Vibe Kanban is "sunsetting" and Crystal was deprecated in February 2026 ([Augment Code](https://www.augmentcode.com/tools/open-source-agent-orchestrators), [Nimbalyst](https://nimbalyst.com/blog/best-agent-management-tools-2026/)). Phone-remote apps lost their edge when Anthropic made Remote Control free. **Wrapper tools get squeezed once vendors ship the feature natively.** AirBridge survives only if it sits where vendors will not go.

**Answer to question 2:** The main competitors are free, built into tools users already pay for, and improving fast. The complaints about them are mostly about **lock-in to one vendor, data going through vendor servers, plain-text-only messages, machines that must stay awake, and Mac/Windows bugs**. Direct user complaint threads were thin in this research, so collect more in interviews.

## Solo power users with mixed vendors are the only good first segment

The total market looks huge, but the real target is small. Evidence: Codex reached about **5 million weekly users in June 2026** ([Axios](https://axios.com/2026/06/02/openai-codex-knowledge-workers)). Claude Code's run-rate passed **$2.5 billion by February 2026** ([Bloomberg](https://www.bloomberg.com/news/articles/2026-02-20/the-surprise-hit-that-made-anthropic-into-an-ai-juggernaut-mlve4nc2)). Cursor passed **$2 billion annualized revenue** in early 2026 ([TNW](https://thenextweb.com/news/cursor-anysphere-2-billion-funding-50-billion-valuation-ai-coding)). A JetBrains survey from mid-2026 found **90% of professional developers use AI coding agents at least weekly, and 68% daily** ([JetBrains Research](https://blog.jetbrains.com/research/2026/08/18/ai-coding-agent-adoption-2026)). The MCP SDK gets about **97 million monthly downloads** ([Digital Applied](https://www.digitalapplied.com/blog/mcp-97-million-downloads-model-context-protocol-mainstream)). There is also overlap between tools. In the 2025 Stack Overflow survey, 17.9% of respondents used Cursor and 9.7% used Claude Code ([Stack Overflow](https://survey.stackoverflow.co/2025/technology)). So some people use more than one vendor, but **no source measures how many use two or more agents, or two or more machines.**

**My estimate (speculation, not sourced):** Assume low tens of millions of people pay for Claude Code, Cursor, or Codex. If 5–10% run agents on two or more personal machines, and 1–5% of those pay for a bridge, that is **about 10,000 to 100,000 paying users, or roughly $2M–$18M a year at $15/month**. That is a fine size for a small company or a solo founder. It is not a venture-scale market unless the product grows into teams later. The cross-vendor part is smaller still.

| Segment | Pain | Budget | Fit for first launch |
|---|---|---|---|
| **Solo/indie developers and freelancers, 2+ machines, 2+ vendors** | High: laptop plus desktop or Mac mini, "human message bus" | Already pay $100–$200/mo for Claude Max or ChatGPT Pro ([TechCrunch](https://techcrunch.com/2025/04/09/anthropic-rolls-out-a-200-per-month-claude-subscription), [TNW](https://thenextweb.com/news/openais-new-100-chatgpt-pro-plan-targets-claude-max-with-five-times-the-codex-access)) | **Best first segment.** $15 is about 7–15% of their AI bill. |
| **Users excluded from Anthropic's feature** (API keys, Bedrock, Vertex, gateways, ZDR) | They cannot use the native feature at all | Often company budgets | **Strong second.** Easy, specific message. Size unknown. |
| **AI/ML engineers with a GPU box** | Laptop must drive a GPU machine | Employer money | Good, but they are skilled at SSH and Tailscale, so they may DIY. |
| **Homelab and local-LLM users** | Own servers; r/homelab ~1.1M, r/LocalLLaMA ~700k members ([Hive Index](https://thehiveindex.com/communities/r-homelab), [AgentsIndex](https://agentsindex.ai/r-localllama)) | Low; prefer free | Good for early free users and word of mouth, weak for revenue. |
| **Students and price-sensitive international developers** | High use; Codex use in India grew 27x in 2026 ([IBTimes](https://www.ibtimes.co.in/codex-weekly-active-users-india-surge-27x-so-far-2026-openai-902440)) | Low | Free or discounted tier only. |
| **Enterprise developers** | Real, but IT controls it | Large, but needs SSO, audit, self-hosting | **Not now.** Anthropic already gives admins switches to block cross-machine messages ([docs](https://code.claude.com/docs/en/cross-session-messaging.md)). |

**Answer to question 3:** Start with solo power users who mix vendors. Add "people who cannot use Anthropic's feature" as a second, sharp message. The market is probably thousands to tens of thousands of payers, not millions.

## $15 a month is possible, but the price must buy privacy and cross-vendor work

Evidence on comparable prices shows that **$15 is high for a single-purpose developer utility.** Tailscale Standard is $8 per user, and its personal plan is free ([Tailscale](https://tailscale.com/pricing/)). Raycast Pro is about $8–10 a month ([Raycast](https://raycast.com/pro)). So "connect my computers" is anchored at **$0**, because Tailscale is free and Claude's own messaging is included in the plan.

There is a good argument in your favor. Your best users already spend **$100–$200 a month** on AI coding. For them, $15 is small if it saves an hour a week. But they will only pay if AirBridge does something the free options do not. That means **cross-vendor handoff, no vendor relay, and moving real files and diffs.**

Freemium math (evidence for benchmarks, my estimate for the result): developer tools convert a median of **about 5% of free users to paid**, and generally 2–7% ([BoldStart / OpenView](https://boldstart.vc/devtoolkit/an-alternative-to-nps-for-dev-tools/), [OpenView](https://openviewpartners.com/blog/freemium-vs-free-trial)). Freemium also gets more signups than a free trial (9% vs 5% of visitors). To reach **1,000 paying users at $15 (about $180,000 a year)**, you need roughly **20,000–50,000 active free users**. That is a lot of free users to support for a niche product. Also note: AI developer tools are moving to usage-based pricing (Warp, Raycast, Cursor) ([Tessl](https://tessl.io/blog/warp-joins-the-pricing-pivot-sweeping-ai-developer-tools)). Since AirBridge is peer-to-peer and does not pay for AI models, a flat price is fine and is a selling point.

**My recommended pricing test (speculation to validate):** a free tier with two machines and limited daily handoffs; Pro at **$8–10/month or about $79–96/year** with unlimited machines and cross-vendor handoff; and test **$15** as the main price or as a higher tier with audit logs and a self-hosted relay. Offer student and regional pricing. Do not decide the price from this report. Decide it from the landing-page test.

**Answer to question 4:** $15 is plausible for a small group of power users, not for the broad market. Freemium with a cheaper Pro tier is the safer default. Test both.

## Platform risk is already real, and security is your selling point or your end

**Platform risk (evidence plus labeled speculation).** For one-vendor use, the risk already happened. Anthropic shipped cross-machine messaging on by default, and it updates Claude Code very fast. Version numbers moved from v2.1.51 to v2.1.3xx during 2026 ([Remote Control docs](https://code.claude.com/docs/en/remote-control)). OpenAI shipped host-to-host handoff with Git state. Cursor is building a fleet of cloud and self-hosted agents. My risk ranking for the next year (speculation): **Anthropic very high** for Claude-to-Claude, and the likely next step is sending files, not just text. **OpenAI high** for Codex-to-Codex. **Cursor medium-high.** **Tailscale medium.** Tailscale already has the private network, identity, an MCP gateway, and developer trust. A "share tasks between agents on my tailnet" feature is a short step for them. Tailscale is also a possible partner or buyer. **GitHub/Microsoft low-medium**, because its coding agent runs in the cloud. No vendor roadmap promises cross-vendor handoff. That is the safest space.

**Security (evidence for the facts, my reasoning for the impact).** A tool that lets an agent on one computer send work and code to an agent on another computer is a powerful attack path. One open-source bridge gives **full shell access by default** after pairing ([agent-bridge](https://ethansk.github.io/agent-bridge/)). In 2025, **46% of developers said they distrust AI output** ([Stack Overflow](https://survey.stackoverflow.co/2025/ai)). Anthropic added an option to require approval before a message leaves the machine (`isolatePeerMachines`), and admin switches to block it ([docs](https://code.claude.com/docs/en/cross-session-messaging.md)). That shows the big vendors think this traffic is risky. Your plan to build your own encrypted peer-to-peer network makes this harder. Users must trust new crypto from an unknown company, instead of Tailscale, which they already trust. To make security a selling point, you need scoped permissions per machine and per folder, human approval for risky actions, a visible log of every handoff, and **open-source networking and crypto code** (or an external audit). Without those, careful buyers will say no.

**"Just use Git or SSH" (steelman).** This objection is strong. The free DIY stack of Tailscale, SSH, tmux, and a phone SSH app is well documented ([tonyh2021](https://tonyh2021.github.io/posts/2026-04-03-tailscale-ssh), [builder.io](https://www.builder.io/blog/claude-code-mobile-phone)). OpenAI's own docs tell users to bring a VPN ([Codex docs](https://learn.chatgpt.com/docs/remote-connections)). One person in #28300 built a cross-machine prototype on Git ([GitHub #28300](https://github.com/anthropics/claude-code/issues/28300)). Git already moves code safely, with history. Your answer must be about **what Git and SSH do not do**: wake the agent on the other machine, pass the task and context, not just the code, return the result to the first agent, and work between different vendors without scripts. If interviewees say "I already have a script for that, and it's fine", that is a clear "no" signal.

**The "no Tailscale install" point is weak on its own.** Tailscale is free and easy, and your best users probably already have it. A built-in network is a convenience, not a reason to pay. Consider letting AirBridge run on top of Tailscale too.

## The verdict: a narrow wedge, tested in four weeks

**Is there a viable wedge?** Yes, but only a narrow one. The wedge is: **"One private bridge between all your coding agents (Claude, Codex, Cursor) on all your computers. Your code and conversations never go through any AI company's servers. It moves real files and diffs, not just chat messages."** If you position it as "Claude Code on two machines", you lose to Anthropic. If you position it as "private networking", you lose to Tailscale.

**Which segment first?** Solo and indie power users who (a) pay $100+ a month for AI, (b) use at least two vendors' agents, and (c) use at least two machines, especially Mac plus Windows or a laptop plus a Mac mini or GPU box. Test a second message for API-key, Bedrock, and privacy-restricted users.

**Interviews (about 15 people, 30 minutes each).** Find people where they already complain: commenters on [Claude Code #28300](https://github.com/anthropics/claude-code/issues/28300) and [#49657](https://github.com/anthropics/claude-code/issues/49657), the [Codex remote-control discussion](https://github.com/openai/codex/discussions/9200), the [HN agent-setup thread](https://news.ycombinator.com/item?id=50366117), [Cursor Remote Control forum threads](https://forum.cursor.com/t/remote-control-from-mac-to-windows-spawns-cursor-agent-locally-and-fails-with-enoent-on-c-paths/166356), and authors of the sync-tool blog posts. Ask about **past behavior, not opinions**. "Would you use this?" gives polite lies. Good questions:

| # | Question | What a strong "yes" sounds like |
|---|---|---|
| 1 | "Walk me through the last time work had to move from one of your computers to another. What did you do, step by step?" | A specific, recent, annoying story |
| 2 | "Which agents do you use on which machines? Why that split?" | Two or more vendors, two or more machines, with a real reason (GPU, OS, always-on) |
| 3 | "How often does this happen in a week, and how long does it take you?" | Several times a week, 10+ minutes each |
| 4 | "Have you tried Claude Remote Control, cross-session messaging, or Codex Remote connections? What stopped you?" | "It's Claude-only", "I use API keys", "I don't want transcripts on their servers" |
| 5 | "What have you built or installed to fix this? What did it cost you?" | Scripts, Tailscale plus SSH plus tmux, an open-source bridge, and still frustrated |
| 6 | "What would make you not trust a tool that lets agents send code between your machines?" | Specific security requirements you can meet |
| 7 | "What do you pay each month for AI tools now? What did you last cancel, and why?" | $100+ a month and a clear sense of value |
| 8 | "If this worked perfectly tomorrow, what would you stop doing?" | A real job disappears, not "it would be cool" |

**Count it as a pass (my suggested bar)** if at least 5 of 15 people describe a recent cross-vendor or cross-OS handoff pain that native tools do not solve, and at least 3 agree to pre-pay or join a paid beta. If most say "Claude's built-in feature is enough" or "I have a script", stop or change direction.

**Landing-page test (two weeks).** Build one page with three headline versions and send equal traffic to each (posts in the communities above, a Show HN, a small ad budget). Version A, cross-vendor: "Let Claude, Codex and Cursor hand work to each other, across all your computers." Version B, privacy: "Agent handoff across your machines. Nothing goes through AI company servers. Works with API keys and Bedrock." Version C, the current pitch: "Link your computers so your AI agents work together. No Tailscale needed." Show price on a second click, splitting visitors between **$8/month and $15/month** (both with a free tier), and ask for an email or a $1–5 refundable pre-order. The developer-tool benchmark of **about 10% visitor-to-signup** ([BoldStart](https://boldstart.vc/devtoolkit/an-alternative-to-nps-for-dev-tools/)) is a reasonable bar for the email step. A pre-order rate of a few percent of visitors at $15 would be a strong signal. Under 1% at $8 is a weak one (my suggested thresholds).

**If the test fails, look at the adjacent pain.** Config, skill, and memory sync across machines has more visible pain and many DIY fixes ([dev.to](https://dev.to/landb/my-claude-code-setup-lived-on-three-machines-and-none-of-them-agreed-17ok), [venpopov.com](https://venpopov.com/posts/2026/syncing-an-ai-assistant-across-machines/)). It could be a feature of AirBridge, or the main product.

## Conclusion

The research changes the question. In 2025 the question was "do people want agents to work across machines?" In late 2026 the answer is "yes, and the vendors built it, each for their own agent." So AirBridge's real question is **"do enough people mix vendors and care about privacy enough to pay for a neutral layer?"** Nobody has measured that, and the small traction of open-source bridges is a warning. The good news is that the vendors' business interests protect the cross-vendor, no-relay space. Anthropic will not make Codex work well, and OpenAI will not make Claude work well.

For you as a solo founder, the practical risk is not building the wrong thing slowly, but building the right thing in the wrong frame. Lead with "all your agents, private" rather than "connect your computers". Make security visible and open, so trust is not your weak point. Let the interviews and the price test decide between $8 and $15. If cross-vendor users do not show up in four weeks, the same technology can serve the larger, proven pain of keeping agents' setup and sessions in sync across machines.

## Addendum (2026-11-23): OpenCrawl, the closest funded competitor

The founder flagged **OpenCrawl** after the main research was done. It was missed in the first pass.

- **What it is:** Y Combinator Fall 2026, 2 founders in San Francisco. "Multiplayer for your coding agents": agents "search each other's histories and talk to each other, across laptops and cloud coding environments."
- **How it works:** a central server (OpenCrawl Cloud, or self-hosted via Docker/Helm). Claude Code and Codex sessions are captured into a shared workspace, with a team message board, MCP search, and a private git remote per workspace for files. Cursor is not stated.
- **Target:** engineering **teams**. Captured sessions are "team-visible by default and can contain sensitive information" (their docs).
- **Pricing:** free to self-host (Apache-2.0); Cloud is free for 100M tokens a month of session history; paid tiers are not announced.
- **Traction (2026-11-23):** 72 GitHub stars, 12 forks, pre-1.0 preview with weekly releases.
- **Implications:**
  - YC funding validates cross-machine agent coordination as a category, and it is a real, fast-moving, free-to-start competitor.
  - AirBridge's differentiation is **personal and private**: one person's own machines, peer-to-peer, no server storing sessions or code, and handoff of tasks and artifacts rather than shared team memory.
  - Lead positioning with privacy. Treat OpenCrawl's team-memory angle as a substitute to probe in interviews: ask whether shared history would solve the pain without handoff.
- **Sources:** https://www.ycombinator.com/companies/opencrawl, https://github.com/getopencrawl/opencrawl-core, https://getopencrawl.com/ (all fetched 2026-11-23).
