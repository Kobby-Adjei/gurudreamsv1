# Rivals own the pieces, not the bundle

**Bottom line in plain words:** As of November 2026, **nobody ships the full combination** you described, meaning one neutral layer where any agent acts on any of your own computers with a previewed plan, narrow passes, verified policy, undo, receipts and a sandbox. But **almost every single piece already exists, and most are free.** Claude Code, Codex and Cursor already give away approvals, phone approval (Claude Code and Codex), OS sandboxes and file undo (Claude Code and Gemini CLI) ([Claude Code permissions](https://code.claude.com/docs/en/permissions), [Codex approvals](https://learn.chatgpt.com/docs/agent-approvals-security), [Cursor security](https://cursor.com/docs/agent/security)). Open-source projects already combine three to five pieces on one machine: **nono** (5,086 stars: sandbox, snapshots, tamper-evident audit), **agentsh** (sandbox, approvals, checkpoints, audit, MCP, on all three OSes), **Tracekit** (approvals tied to exact arguments, Certificate-Transparency-style receipts) and **Caracal** (passes that can only shrink, OPA policy, approvals, audit) ([nono](https://github.com/nolabs-ai/nono), [agentsh](https://github.com/canyonroad/agentsh), [Tracekit](https://github.com/Cygnux-Labs/Tracekit), [Caracal](https://github.com/Garudex-Labs/caracal)). **Tailscale Aperture** is the most dangerous single competitor. Since August 2026 it is generally available, aimed at "individuals and homelab users", spans all your machines, lets coding agents SSH into them, and logs every agent action ([Tailscale Aperture GA](https://tailscale.com/blog/aperture-ga)). So the honest answer to "how close?" is: **glue four open-source projects to Tailscale and you have most of the spec.** Two things are genuinely open. The first is a **real plan preview**: run the agent's plan in a throwaway copy, show the diff, approve on the phone, then apply. I found only per-call holds, never a whole-plan diff of local effects. The second is **enforcement on your other machines, where your daemon is the only door in.** The sharpest wedge combines both: "Your agent proposes, your phone approves the diff, your other machine applies it in a sandbox, and you can undo it." Build that first on macOS and Linux, on top of Tailscale and existing sandboxes. Defer Biscuit passes, Lean proofs, public transparency logs, Windows and your own P2P network.

How to read this report: a sentence with a citation is **evidence** from a source checked on 2026-11-24. Sentences that start with **"My read"** or are marked *speculation* are my reasoning, not measured facts. Star counts are GitHub search API values from 2026-11-24. Many 2026 AI-security repos have inflated stars, so treat stars as weak signals.

The first thing to accept is that four of your six pieces are now **standard, free features inside the agents themselves**. The table below shows what each vendor ships. "Single vendor" is the common limit.

Three things are missing from every vendor. **No vendor works across vendors**: Copilot's managed permissions apply only to Copilot, and Claude Code and Codex each have their own settings ([GitHub changelog](https://github.blog/changelog/2026-09-09-enterprise-managed-permissions-for-github-copilot-agent-operations)). **No vendor undoes anything beyond local files**, and Claude Code's own docs say rewind is "not a replacement for version control" ([checkpointing](https://code.claude.com/docs/en/checkpointing)). **No vendor documents signed or tamper-evident logs.** Multi-machine approval exists, but each vendor builds it only for itself. Codex makes you "pair your phone with each host" ([Codex remote](https://learn.chatgpt.com/docs/remote-connections)), and Claude Code works per process ([Remote Control](https://code.claude.com/docs/en/remote-control)). A person using both agents on two machines today has at least two approval apps and several pairings.

My read: these gaps are real, but the vendors already own the user's attention. The ccundo project is the warning. It reached 1,399 stars, then stopped when Claude Code shipped native checkpoints, and its description now says "claude now natively supports this feature" ([ccundo](https://github.com/RonitSachdev/ccundo)). **Any feature that improves one vendor's agent will be copied by that vendor.** Only cross-vendor and cross-machine features are protected by the vendors' own business interests.

## Tailscale Aperture and enterprise tools close in from two sides

Outside the agent vendors, the market splits into a consumer threat and a crowd of enterprise sellers.

**Tailscale Aperture is the threat to take most seriously.** It moved from private alpha (January 2026) to GA on 2026-08-26. The GA post targets "individuals and homelab users", which is exactly your buyer ([Aperture GA](https://tailscale.com/blog/aperture-ga)). At GA it proxies LLMs, MCP servers and APIs. It sets default tool permissions that projects can widen or narrow. It keeps Tailscale ACLs in force. It adds MCP endpoints that let coding agents join machines to the tailnet and **SSH into them, with the user approving each machine**. It also says "all agent actions are logged" ([Aperture GA](https://tailscale.com/blog/aperture-ga)). In November 2026 it added skill sharing across agents through its MCP endpoint ([Tailscale skill sharing](https://tailscale.com/blog/skill-sharing-with-aperture)). Pricing is not published. The beta was included in Personal plans ([public beta](https://tailscale.com/blog/aperture-public-beta)). What Aperture does **not** have, as far as the sources show: no sandbox, no undo, no plan preview, no narrow passes, and no tamper-evident receipts. My read: today Aperture hands your agent an SSH session, which means full shell power on the other machine. Your product would hand the agent a narrow pass, a sandbox, a diff and an undo button. That difference is your whole pitch, and Tailscale could close it if it chose to. *Speculation:* Tailscale is as likely a partner or buyer as a killer, because your product needs a private network and Tailscale already has one people trust.

**Enterprise security vendors already cover many agents, but only for companies.** Zenity enforces through each agent's native hooks plus an MCP gateway. It covers Claude Code, Cursor, Codex and Copilot with "no endpoint sensor required" ([Zenity](https://zenity.io/use-cases/agent-type/coding-personal-agents)). Lasso does the same through lifecycle hooks ([Lasso](https://www.lasso.security/use-cases/ai-coding-assistants)), and Operant adds an endpoint agent ([Operant](https://www.operant.ai/solutions/code-agents)). None publishes pricing, and none offers undo. The category is consolidating fast. Palo Alto bought Protect AI (~$634.5M), SentinelOne bought Prompt Security (~$160M), CrowdStrike bought Pangea (~$223M) and Check Point bought Lakera ([deal tracker](https://guptadeepak.com/agent-security/deals/), [SiliconANGLE](https://siliconangle.com/2025/09/16/crowdstrike-check-point-extend-ai-security-capabilities-new-acquisitions/)). My read: this shows that "cross-agent control through native hooks" is a proven design. It also shows the enterprise lane is taken by companies far bigger than you. Your lane is the individual.

**MCP gateways already use Cedar and approval.** Docker's enterprise MCP policy is **written in Cedar** ("forbid overrides permit") and has an **approval mode** for sensitive calls ([Docker MCP policy](https://docs.docker.com/ai/governance/reference/mcp-policy/)). Cloudflare's MCP portals reached GA in September 2026 with logging and DLP ([Cloudflare changelog](https://developers.cloudflare.com/changelog/post/2026-09-24-mcp-portals-ga/)). The important limit: gateways see MCP traffic, but **they do not see local shell or file actions**. That limit applies to your design too, as the "only door" argument below explains.

**Identity vendors handle tokens for cloud APIs, not your laptop.** Okta Cross App Access, Aembit and Auth0 for AI Agents handle delegated credentials and async approval for SaaS APIs ([Aembit](https://aembit.io/press-release/aembit-launches-support-for-okta-cross-app-access-extending-enterprise-identity-controls-to-ai-agents/), [Arcade comparison](https://www.arcade.dev/blog/best-ai-agent-authentication-platforms/)). **Rubrik Agent Rewind** is the one commercial "agent undo" product. It pairs an immutable activity record with selective rollback, sold to enterprises ([Rubrik](https://www.rubrik.com/insights/ai-issues-take-control-with-rubrik-agent-rewind); details unverified, the page blocked fetching). **Microsoft Execution Containers (MXC)** went GA on 2026-10-07. MXC is a cross-platform, JSON-policy sandbox for AI agents built on AppContainer, Seatbelt and Bubblewrap, and Copilot and Codex already use it ([Windows Developer Blog](https://blogs.windows.com/windowsdeveloper/2026/10/07/microsoft-execution-containers-policy-driven-containment-for-ai-agents/)). My read: MXC turns "neutral sandbox policy for any agent" into a Microsoft standard. Build on it rather than against it.

The pieces in detail. **nono** is the strongest project by traction: 5,086 stars, 340 forks and 255 open issues, which suggests real users. Its README says it was "built by the team that brought you Sigstore" ([nono](https://github.com/nolabs-ai/nono)). **agentsh** is the most complete by features. It has 1,516 commits, auto-checkpoints before `rm`, `mv` and `git reset`, rollback with dry-run, and MCP controls that catch data leaking between servers ([agentsh](https://github.com/canyonroad/agentsh)). **Tracekit** is the reference design for receipts. It is "built like Certificate Transparency", but its own README admits the policy rules "match text and tool names" and are "tripwires, not a wall" ([Tracekit](https://github.com/Cygnux-Labs/Tracekit)). **Tenuo** is the cleanest narrow-only pass for MCP. Its README says it was inspired by Macaroons, Biscuit and UCAN, and a child warrant that tries to widen its parent fails with `MonotonicityError` ([Tenuo](https://github.com/tenuo-ai/tenuo)). The base technologies are mature and active. Cedar has 1,895 stars, Biscuit 1,173 (now under Eclipse), OPA 12.5k, and Anthropic's sandbox-runtime 7,247 ([Cedar](https://github.com/cedar-policy/cedar), [Biscuit](https://github.com/eclipse-biscuit/biscuit), [sandbox-runtime](https://github.com/anthropics/sandbox-runtime)). Nobody with real adoption has packaged **Biscuit with MCP**. A GitHub search for that returned nothing meaningful.

**Research says the same thing.** AgentCap (arXiv, 31 October 2026) wraps every MCP tool call with session-bound capability tokens whose budget and lifetime only narrow at each hop ([AgentCap](https://arxiv.org/abs/2611.00729)). DelegateGuard (October 2026) uses purpose-bound capabilities that "narrow but never widen". It also warns that **narrowing alone cannot stop leaks to sinks that are already allowed** ([DelegateGuard](https://arxiv.org/abs/2610.16005)). Undo research is blunt about limits. Atomix says a checkpoint "cannot recall an email, booking or remote API update" ([Atomix](https://arxiv.org/abs/2602.14849)). "Safe to Resume?" argues that a restored checkpoint can resume a state that "never coexisted in any valid history" ([Safe to Resume?](https://arxiv.org/abs/2608.29381)). "Notarized Agents" points out that hash chains do not prove completeness, because an operator can simply withhold receipts ([Notarized Agents](https://arxiv.org/html/2606.04193)). Standards are not ready. The IETF OAuth group has about seven competing delegation drafts and none has been adopted ([IETF interim slides](https://datatracker.ietf.org/meeting/interim-2026-oauth-03/materials/slides-interim-2026-oauth-03-sessa-ietf-individual-draft-analysis-00)).

**Many early projects already stalled**, and the reasons are lessons for you. Invariant Labs' gateway went quiet after Snyk bought the company ([invariant-gateway](https://github.com/invariantlabs-ai/invariant-gateway)). Trail of Bits archived mcp-context-protector ([repo](https://github.com/trailofbits/mcp-context-protector)). eqtylab/mcp-guardian has had no push since August 2025 ([repo](https://github.com/eqtylab/mcp-guardian)). strongdm/leash, the most visible Cedar-for-agents project, has been idle since April 2026 ([leash](https://github.com/strongdm/leash)). My read on the pattern: vendors absorb the feature, acquirers absorb the team, or a crowd of near-identical "agent firewall" and "receipts" repos splits attention. Dozens of receipt and firewall repos were created in 2026 alone.

**How close is the combination, honestly?** My read: Tenuo passes + Cedar policy + nono or agentsh sandbox and snapshots + Tracekit receipts + Tailscale transport would give you **most of the spec, all from Apache or MIT-licensed open source**. Nobody has assembled it. But the parts are lying on the table, so a well-funded team could assemble them in a quarter. *(Speculation.)* Note one gap in the evidence: search coverage of small indie projects was limited, so a tiny project doing exactly this may exist unseen.

## macOS and Linux work without admin; Windows does not

The OS question has a clear answer. **macOS and Linux can do everything you need at user level. Windows needs one admin prompt or Microsoft's MXC.**

| Piece | macOS | Windows | Linux |
|---|---|---|---|
| **Sandbox an agent's commands to a folder** | Seatbelt (`sandbox-exec`): deprecated since 2016 but used by Claude Code, Codex, Cursor and MXC ([Cursor](https://cursor.com/blog/agent-sandboxing)) | No clean no-admin option. Codex's unelevated mode has "weak" network protection. Strong mode needs admin setup that creates sandbox user accounts ([OpenAI](https://openai.com/index/building-codex-windows-sandbox/)). MXC on Windows 11 is GA ([MXC](https://blogs.windows.com/windowsdeveloper/2026/10/07/microsoft-execution-containers-policy-driven-containment-for-ai-agents/)) | bubblewrap or Landlock+seccomp, unprivileged ([Landlock](https://docs.kernel.org/userspace-api/landlock.html)). Ubuntu 24.04's AppArmor may need **one sudo** ([Claude Code](https://code.claude.com/docs/en/sandboxing)) |
| **Network fence** | Allow only a localhost proxy, then filter by host; no admin ([srt](https://github.com/anthropic-experimental/sandbox-runtime)) | Kernel-level egress blocking needs admin once (firewall or WFP per sandbox account) ([srt](https://github.com/anthropic-experimental/sandbox-runtime)) | Empty network namespace + proxy; no admin |
| **Per-folder undo** | `clonefile` copy-on-write clones: near-zero space, no admin ([clonefile(2)](https://opensource.apple.com/source/xnu/xnu-4570.31.3/bsd/man/man2/clonefile.2.auto.html)) | Block cloning only on ReFS or Dev Drive. Most users run NTFS, so **plain copies** ([Microsoft](https://learn.microsoft.com/en-us/windows/win32/FileIO/block-cloning)) | btrfs snapshot of a subvolume you own, or `cp --reflink` ([kernel commit](https://android-kvm.googlesource.com/linux/+/d024206133ce21936b3d5780359afc00247655b7)) |
| **Whole-disk snapshot** | Whole-volume only. Time Machine deletes snapshots after 24 hours. Mounting one needed root in user reports ([Eclectic Light](https://eclecticlight.co/2026/09/09/take-control-of-snapshots/)) | VSS needs admin or backup privileges ([Microsoft](https://msdn.microsoft.com/en-us/library/aa381517(v=vs.85).aspx)) | Needs a specific filesystem layout and root setup |
| **Phone approval and background daemon** | No OS barrier: a LaunchAgent | No OS barrier: a startup task | No OS barrier: a systemd user service |

Five practical consequences follow. **First**, the realistic undo design is to clone each granted folder before every agent action, and to store the clones **outside anything the agent can write**. Otherwise the agent can delete its own checkpoints. Whole-disk snapshots are too coarse, need admin, and expire. **Second**, sandboxing should wrap the processes the agent launches, not the whole machine. Watching the whole machine needs Apple's restricted Endpoint Security entitlement on macOS and signed drivers on Windows. That is heavy for a solo founder (this point comes from background knowledge and was not re-verified). **Third**, laptops sleeping will pause pending approvals, so every approval should **time out to "deny"**. **Fourth**, phone approval has no OS limits. Hobby tools already push Claude Code permission prompts to phones through ntfy ([claude-remote-approver](https://github.com/yuuichieguchi/claude-remote-approver)). **Fifth**, and this one is not covered by the research notes: a normal VPN network device (TUN) usually needs admin to install. Tailscale's user-space mode and its embeddable library are reported to avoid that. **Verify this before you promise "no admin" for the P2P part.**

One security point decides your architecture. Tools that only intercept tool calls (hooks or MCP proxies) **can be bypassed by any shell command the agent runs**. Claude Code's own sandbox covers Bash but not MCP servers or hooks ([Claude Code sandboxing](https://code.claude.com/docs/en/sandboxing)). Anthropic's sandbox README warns that allowing Apple Events means "the sandbox no longer provides code-execution isolation" ([srt](https://github.com/anthropic-experimental/sandbox-runtime)).

**The "only door" argument.** This is my read, and I think it is the most important idea in this report. On the machine where the agent runs, your layer is easy to get around. The agent still has its own shell, file and web tools, so a hook or MCP proxy is only a tripwire unless you also wrap the whole agent in a sandbox. On **another** machine, the agent has no native tools at all. If your daemon is the only way in, every action must pass through your pass check, your sandbox, your diff and your undo, and **the enforcement is real**. That is exactly the cross-machine scenario of the original AirBridge idea. Vendors can't cover it neutrally, and Aperture covers it only with raw SSH. The cross-machine part turns your weakest point (a bypassable wrapper) into your strongest one.

**Threats, ranked bluntly** (*speculation* about future moves; current facts are cited above). **Anthropic and OpenAI: very high**, but only for their own agents. Codex already shows diffs on the phone, so a "dry-run then diff" step is a short step for them. **Tailscale Aperture: high.** It owns the network, the identity, the homelab audience and MCP SSH tools. Adding "approve this command" or "run in a sandbox" to its SSH tool would take most of your wedge. **nono: high.** It already has sandbox, snapshots and signed audit, a Sigstore team (so public-log anchoring is natural for them), and real users. Remote nodes and phone approval are a modest addition. **agentsh: medium-high.** It has the most features, covers three OSes, and has WebAuthn approvals, but only 412 stars. **Tracekit: medium.** It has the best receipts and argument-bound approvals, and could add sandbox and undo through Tracekit Box. **Caracal: medium.** It is the passes-plus-policy control plane, but it has no sandbox or undo and leans enterprise. **Microsoft MXC: medium.** It could become the default neutral sandbox policy, which helps you if you build on it. **Zenity or Lasso launching a prosumer tier: low-medium.**

## The wedge: approve a diff, apply it on another machine

**Verdict.** Do not sell "a verified, capability-based, transparency-logged permission layer". Each of those words names something commoditized or something buyers do not pay for. Sell one concrete moment: **"Your agent on the laptop wants to change something on your desktop or Mac mini. You get a phone notification showing exactly what will change. You tap approve. It runs inside a sandbox on that machine. One tap undoes it."** It works with any agent that speaks MCP. That is the plan preview plus remote enforcement, the two open spots, wrapped in the cross-vendor neutrality vendors won't provide. My read: this is also the version where the earlier AirBridge research applies. Your best users are solo power users who mix vendors across two or more machines.

**Smallest first version** (my recommendation, *speculation* until tested). **Target machines: macOS and Linux only.** `clonefile` or reflink copies plus Seatbelt or bubblewrap give you sandbox and undo with no admin. Windows waits until you can build on MXC. **The agent side can be any OS**, because it is only an MCP client. **Network: run on Tailscale** (or its embeddable library) rather than your own P2P stack. The earlier research already found that "no Tailscale needed" is not a reason to pay. **One MCP tool, `propose`**: the agent sends commands and a target folder. The remote daemon runs them in a sandboxed copy-on-write clone with the network off. It returns the real file diff plus a list of anything it blocked: network, pushes, installs, paths outside the folder. **Phone approval through a passkey-protected web page or ntfy push**, with no native app. Tracekit already proves passkey web approvals work. Each approval is bound to a hash of the exact plan and times out to deny. **Apply means swapping in the approved result and keeping the old copy**, so `undo` restores it. **Grants are simple**: folder, allowed hosts, expiry. Write them in Cedar if embedding it is cheap, but don't market proofs. **Receipts are a local signed hash chain** (consider reusing Tracekit's format rather than inventing one). Defer Biscuit sub-agent passes, Lean or SMT subset proofs, public transparency-log anchoring, GUI and computer-use actions, undo of external effects, and Windows. Reuse nono or srt rather than writing a sandbox. Both are open source.

**How you would know you're wrong.** Use the 15-interview plan from the earlier AirBridge research and add three questions. Have you ever let an agent change a machine you weren't sitting at? Did Claude's `/rewind` or Codex's phone diff fail you? Would you pay to make remote agent actions approvable and undoable? Stop or change direction if most people say "I just use Tailscale SSH and git" or "I only run agents on one machine". Also stop if Aperture adds sandboxed, approvable SSH actions before you have users.

## Conclusion

The research changes the question from "is anyone building this?" to "which part still belongs to nobody?". Sandboxes, file undo, policy engines, per-call phone approval and signed logs now exist in many products. The "formally verified" and "transparency log" parts sound strong, but they are inherited from AWS's Cedar and Google's CT design. They help you sleep at night, but they will not make anyone buy. What nobody owns is a **neutral, enforceable door into your other machines** that shows a real diff before anything happens. Its value comes from geometry, not cryptography. On a remote machine your layer is the only path in, so its guarantees actually hold.

For a solo founder, the risk is not that the idea is wrong. The risk is that you spend months on the impressive parts (Biscuit, Lean, your own P2P network) while Tailscale or nono adds the boring part that users notice: "approve this diff on your phone." So build the boring part first, on top of their open-source work, and make the advanced security pieces version two, once users ask for them.
